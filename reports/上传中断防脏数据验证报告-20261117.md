# 上传取消、断网与退出防脏数据验证报告

本次发现并本地修复三类问题：上传完成但未入库的文件失去清理引用；主图保存响应丢失后重试重复创建；附加图已关联但响应丢失时被客户端误删。主图、标签确认、详情附加图以及账号撤销/本人清空均已联动处理。**云端配置尚未启用，本地代码完成不代表线上已经具有回收保障。**

## 1. 最终行为

| 场景 | 新流程 |
| --- | --- |
| 取消系统选图 | 不建会话、不传文件，保留原列表 |
| 登记失败/响应丢失 | 未取得登记不传图；云端以稳定请求 ID 登记，设备保留最小补偿队列 |
| 取消上传/清空/切 Tab/返回 | 停止后续阶段、abort 上传句柄，先关闭会话，云端仅回收未提交文件 |
| 短后台/系统选图与预览 | 暂停后续阶段，回前台重鉴权/读会话后继续；24h期限不延长 |
| 原图/缩略图/检查/分析失败 | 文件位置仍在台账；重试放弃旧尝试、使用新 job/path，旧响应不影响新批 |
| 主图保存结果未知 | 查询任务，已提交标保存并立即更新脏标记；无法确认则锁定编辑/重复保存，只核对或放弃 |
| 附加图保存结果未知 | 整组查询/同组幂等重试，不裸删文件；事务读取最新 extraFiles 后追加，最多8张 |
| 保存与取消/回收竞争 | 写同一会话/任务事务：保存先成功保留作品；关闭或 cleaning 先成功拒绝提交 |
| 删除/引用查询失败 | 保留准确 ID、状态、租约和重试时间，不用删除台账替代删除文件 |
| 强制关闭 | 无退出回调也可依据云端登记找到文件；等待24h过期加定时调度和失败重试 |

新增 `accessGate/upload-jobs.js` 与 `utils/upload-flow.js`，联动 accessGate 入口/配置/包与锁、API/App、upload/confirm/detail/my。新增私有集合 uploadJobs，账号新增永久 uploadVersion/清理游标；无新页面路由或业务环境变量。`adminMaintenance`、检测/AI、反馈/作品集与筛选上下游核对，不扩大运维名单、不改历史未知孤儿。

回收每10分钟，单轮45秒预算/最多10图，短租约和游标防重复。cleaned 首次成功后10分钟、随后每日重扫，观察7天，末次明确成功才移除图片台账。committed 不删文件，7天后压缩幂等结果；关闭会话保留拒绝旧 requestId 的摘要，空/已归档队列退出调度，防旧请求重新创建。压缩后旧提交拒绝并要求查看现有作品。
