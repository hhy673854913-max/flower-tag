# 花艺师作品集分享规格

## 为什么

花艺师需要通过一个微信分享入口展示自己的多件作品，既能直接分享全部本人作品，也能手动挑选作品组成精选作品集。当前仓库只有单件作品分享，缺少作品集授权、管理入口和接收方展示页面。

## 变更内容

- 在「我的」新增「作品集分享」入口，提供「分享全部作品」「挑选作品分享」两种方式，以及已创建链接的预览、再次分享和停止分享。
- 新增独立作品集分享页：作者名称、作品数量、作品网格、分页加载、只读详情与原图/附加图预览。
- 全部作品链接展示本人当前所有未删除作品，后续新增作品自动纳入；精选链接展示创建时明确选中的作品，新增作品不自动纳入。
- 作品集授权与现有单件分享分别管理；创建、停止作品集分享均不批量修改作品的 `isPublic/shareToken`。
- 服务端统一执行身份、归属、令牌、分享范围、作者有效状态和删除状态检查。
- 补充修改影响范围清单、需求文档、开发日志、代码说明、功能说明、技术规范；同步检查 README 和环境变量说明。
- 本次保持原生微信小程序 JS/WXML/WXSS 与现有云开发结构。

## 影响范围

- 影响能力：本人作品管理、账号状态、微信分享、访客只读查看、作品删除、账号撤销与清理。
- 现有文件：
  - `miniprogram/pages/my/my.js/wxml/wxss`：入口、身份状态与撤销提示。
  - `miniprogram/pages/detail/detail.js/wxml/wxss`：作品集上下文只读详情、原图重新鉴权、单件分享说明。
  - `miniprogram/utils/api.js`：作品集管理、公开列表和详情接口。
  - `miniprogram/app.json`：注册新页面。
  - `miniprogram/app.js`：默认分享包装与页面独立分享回调兼容；避免访客内容进入本人缓存。
  - `cloudfunctions/accessGate/index.js`：授权、分页、详情、失效与撤销联动。
  - `cloudfunctions/adminMaintenance/index.js`：核对已有 `shareLinks` 清理配置与管理员保护。
  - `pages/index`、`pages/filter`、上传确认和删除链路：回归现有个人列表、刷新和单件分享。
- 拟新增页面：
  - `miniprogram/pages/portfolio-manage/portfolio-manage.js/json/wxml/wxss`：管理、挑选与作者预览入口。
  - `miniprogram/pages/portfolio-share/portfolio-share.js/json/wxml/wxss`：接收方作品集展示。
- 拟使用集合：`shareLinks`；保留 `records`、`accessAccounts`、`admins` 原有含义。当前运维配置提及 `shareLinks`，不代表仓库已有业务实现；实现前检查实际集合和历史字段兼容性。
- 新环境变量：不预设新增；使用现有 `accessGate` 管理员配置。部署需要核对集合权限和索引。
- 文档现状：需求记录 v1.4.0 列表分享已上线，但本地无对应实现；本规格描述本次拟新增能力，不能把历史产品记录或本次规划写作已部署、已验收。

## 新增需求

### 需求：本人作品集管理入口

系统必须为已开通花艺师和管理员提供作品集分享入口，只允许管理本人的作品和链接。

#### 场景：进入作品集管理

- **当**有效花艺师或管理员从「我的」进入「作品集分享」
- **则**显示两种分享方式和本人已创建链接，展示链接类型、状态及预览/分享/停止操作。
- **则**管理员身份不赋予创建他人作品集链接的能力。

#### 场景：未开通或身份失效

- **当**未开通用户尝试进入管理路由，或页面打开后账号被撤销
- **则**服务端拒绝创建和管理链接，页面提示账号状态并提供前往「我的」的入口。

### 需求：直接分享全部本人作品

系统必须在作者明确确认后创建全部作品链接。开启前必须告知：链接持有者可查看全部本人作品及附加图，后续新增作品也会自动展示，包括未开启单件分享的作品。

#### 场景：创建全部作品链接

- **当**作者有可展示作品，确认「分享全部作品」
- **则**创建独立令牌并进入作品集预览，提供微信「分享给好友」按钮。
- **则**按保存时间倒序展示本人所有未删除、非删除中作品，无须逐件开启单件分享。

#### 场景：之后新增或删除作品

- **当**作者在链接有效期间新增作品或删除作品
- **则**后续读取自动包含新增作品、排除已删除或删除中的作品。
- **则**全部作品被删除后保留有效链接的空作品集状态；没有作品时禁止首次创建。

### 需求：手动挑选作品分享

系统必须允许作者在本人作品列表中多选，创建一个仅包含所选作品的独立链接。两种方式可同时使用，多个精选链接互不覆盖。

#### 场景：创建精选作品集

- **当**作者选择至少一件本人有效作品并确认分享
- **则**创建精选链接，记录已验证的作品 ID，按作品保存时间倒序展示所选作品。
- **则**选择界面分页加载，显示选中数量；翻页、重试不丢失已有选择；未选任何作品时不能创建。
- **则**每次创建新精选链接不替换已有链接。本期调整精选范围通过重新挑选并创建新链接完成。

#### 场景：新增作品与伪造选择

- **当**作者之后上传新作品
- **则**已有精选链接不自动纳入新作品。
- **当**请求混入他人作品、不存在作品或删除中的作品
- **则**服务端拒绝整次创建并提示重新选择，不静默扩大范围；重复 ID 去重。

#### 场景：所选作品被删除

- **当**精选作品被删除
- **则**后续列表、详情、原图请求不可再获取该作品，数量按当前可展示作品计算。
- **则**全部所选作品被删除时展示空状态，不替换为作者全部作品。

### 需求：作品集接收方分享页

系统必须允许未开通的微信用户凭有效作品集令牌只读浏览，不要求输入校验码。

#### 场景：打开有效分享卡片

- **当**接收方打开 `/pages/portfolio-share/portfolio-share?portfolioToken=...`
- **则**展示作者现有名字（缺失时显示「花艺师」）、全部/精选标识、当前作品数量和双列作品网格。
- **则**首屏按 20 件加载，继续滚动按需加载；列表只取得缩略图，旧作品无缩略图时回退主图。
- **则**点击作品进入同一授权范围内的只读详情，可查看现有展示标签及附加图，原图按需获取。
- **则**页面不展示编辑、删除、上传、补图、作者账号管理或个人词库操作。
- **则**作者打开自己的分享链接也保持接收方只读视图，管理通过独立管理入口完成。

#### 场景：转发作品集

- **当**作者或接收方在有效作品集页分享给好友
- **则**微信卡片指向同一作品集令牌，标题使用「作者名字的花艺作品集」，封面使用已授权首件作品缩略图。
- **则**无封面时使用不含作品图片的默认卡片；不生成假作品图。
- **则**只读详情不自动开启作品的单件分享；本期转发作品集使用作品集页面入口。

#### 场景：加载状态

- **当**首次加载、作品为空、后续加载失败或图片失败
- **则**分别展示加载提示、空状态、可重试提示和图片失败提示。
- **则**后续页失败保留已成功展示的作品；重复点击不会重复请求或重复追加；刷新、快速返回及过期请求不串数据。
- **则**分享页提供「进入花艺图库」入口，返回无页面栈时有可靠去向，进入首页不将作者作品带入接收者的本人列表。

### 需求：独立授权及链接生命周期

系统必须默认不对外开启作品集分享，只在明确创建后允许读取。停止、撤销和删除规则必须在云端落实。

#### 场景：停止某个作品集链接

- **当**作者确认停止分享
- **则**仅该链接失效；相同作品的其他作品集链接及单件分享保持各自状态。
- **则**旧令牌不可再次启用；重新分享创建新令牌，后续读取旧令牌失败。

#### 场景：作者被撤销后重新开通

- **当**管理员撤销作者权限或账号处于清理中
- **则**立即阻断其全部作品集的列表、详情和图片链接获取，不依赖后台作品清理是否成功。
- **则**撤销同时永久失效旧作品集令牌；后续重新开通不能复活旧令牌。

#### 场景：持有已获取的内容

- **当**分享停止或作品删除
- **则**新的服务端请求被阻断；已下载图片或此前签发且仍有效的临时链接无法追溯收回，开启与停止提示准确表述这一边界。

### 需求：服务端范围检查和分页

系统必须将令牌作为服务端授权入口，不能信任客户端传入的作者身份、管理角色或作品范围。

#### 场景：读取列表与详情

- **当**接收方携带令牌调用公开读取接口
- **则**每次验证链接有效状态、作者当前有效状态、作品归属及删除状态。
- **则**详情和原图请求额外核对作品属于该令牌授权范围，不能通过替换作品 ID 读取同作者未选作品或其他作者作品。
- **则**仅返回展示字段白名单，不返回作者 openid、校验码、账号数据、存储路径前缀或其他分享令牌。
- **则**仅为本次允许展示的图片签发临时 URL，访客不通过前端直接读取数据库或批量换取任意文件 URL。

#### 场景：超过一页的作品集

- **当**作品超过 20 件或精选 ID 超过单次数据库查询容量
- **则**服务端按稳定排序分页、分批查询，限制并校验分页参数，数量为当前可展示总数，不沿用首页 100 条或筛选 60 条截断。
- **则**静态数据翻页不漏图、不重复；并发新增/删除情况下以刷新获取最新列表，不承诺跨请求事务快照。

## 技术约束与接口草案

- 拟新增 `accessGate` action：
  - `createPortfolioShare({ mode: 'all' | 'selected', recordIds? })`：通过 `userWrite` 校验真实调用者、验证所选作品；生成与单件令牌相同强度的随机令牌。
  - `listPortfolioShares({ cursor? })`：只返回本人链接的管理摘要，分页加载。
  - `stopPortfolioShare({ id })`：只允许本人操作，幂等停止。
  - `readPortfolioShare({ token, cursor?, limit? })`：无需开通，返回作者展示名、类型、可展示总数、当前页作品展示信息和下一页游标。
  - `readPortfolioRecord({ token, recordId, original? })`：无需开通，返回白名单详情与授权图片 URL；原图预览重新鉴权。
- 拟定 `shareLinks` 字段：`type: 'portfolio'`、服务端写入的 `ownerOpenid`、`mode`、精选模式 `recordIds`、随机 `token`、`enabled`、`createdAt`、`disabledAt`。公开接口不返回管理字段。
- 只存授权及作品引用，不复制作品记录、图片或标签；全部模式不存全量作品 ID。
- 多选数据和接口大小按云数据库及云函数实际容量验证，必要时分批；超限必须明确提示，不截断、不创建缺失作品的链接。
- 索引至少核对令牌定位、本人链接分页、本人作品排序查询；兼容 `records._openid` 与历史 `ownerOpenid` 归属规则。
- `shareLinks` 客户端读写关闭，业务访问统一走云函数。执行前核对历史集合及线上权限，不能覆盖不兼容历史数据。
- 创建/停止授权与撤销使用现有账号事务冲突机制。撤销事务必须留下不可复活的失效依据（例如账号作品集授权版本，链接记录创建版本），不能仅依赖后续批量停止链接。
- 清理链接不删除被引用的图片；图片生命周期继续由原作品删除链路负责。「我的」清空作品后链接为空，撤销/运维清理核对授权残留处理。
- 视觉：沿用浅色底、绿色强调和现有圆角间距；作者信息克制，作品为主。管理页与访客页明确区分；不新增名片编辑、头像上传、联系方式、海报、筛选、客户选款、公共大厅或访问统计。

## 修改需求

### 需求：现有单件分享说明与只读详情

系统必须保留单件分享协议和原有权限，并使提示与新增作品集授权一致。

#### 场景：关闭单件分享

- **当**作者停止单件分享
- **则**该作品的单件分享令牌失效，但已授权作品集仍可展示该作品。
- **则**提示说明单件与作品集分别管理；不再笼统声称「其他作品仍保持私密」或「已有全部分享都停止」。

#### 场景：现有功能回归

- **当**作者使用本人作品墙、筛选、详情编辑、单件分享或管理员管理
- **则**原有路由、字段、账号权限和个人数据隔离保持兼容。

## 移除需求

无。
