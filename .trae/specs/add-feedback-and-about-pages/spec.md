# 反馈与关于页面规格

## 为什么

用户需要从「我的」提交问题和建议，并附带排查所需信息；现有关于弹窗无法承载版本说明与历史日志，且介绍文案已过时。

## 变更内容

- 「我的」公共菜单增加「意见反馈」，原「关于与隐私说明」点击进入独立页面；未开通用户也可使用。
- 反馈页提供必选类型、必填内容、选填手机号，提交前二次确认，保存到云端并显示成功状态。
- 关于页展示实际版本、对应版本更新内容、可点击打开的隐私说明弹窗，以及按新到旧平铺的历史日志。
- 用户明确授权「直接不用我确认，按照你提供给我的方案直接执行」，本规格创建后直接进入实施，不再次请求批准。
- 保留原生微信 JS/WXML/WXSS，不迁移框架；本次只交付本地代码和文档，不提交、部署、发布或修改线上数据。

## 影响范围

- 新页面：`pages/feedback/feedback`、`pages/about/about`；入口为 `pages/my/my.js/wxml`，注册在 `app.json`。
- 共享信息：新增 `utils/app-info.js` 管理可信产品版本历史、当前构建新增内容及运行版本读取；反馈与关于页共同使用。
- 接口：`utils/api.js` 新增 `submitFeedback(payload)`；`cloudfunctions/accessGate/index.js` 分发到独立 `feedback.js`，复用真实 OPENID、账号与管理员查询、文本审核权限。
- 数据：新增 `feedbackRecords` 私有集合，客户端读写关闭，由云函数写入、维护人员从云控制台排查；不新增反馈列表、回复管理或图片附件。
- 维护：实施前补 `修改影响范围清单.md` 模块地图，实施后同步需求、开发日志、代码说明、功能说明、技术规范、README、环境变量及影响清单。
- 部署要求：创建或核对 `feedbackRecords` 和权限，更新部署 `accessGate`，编译前端；幂等按文档 ID 定位，无预设新增复合索引或环境变量。
- 关联规格：已完成 `add-florist-portfolio-sharing`、`edit-portfolio-metadata` 的本地记录保留；本次不重置其勾选或推定历史部署已完成。

## 新增需求

### 需求：提交意见反馈

系统必须让真实微信用户在未开通、已开通、管理员或清理中状态均可提交反馈，不因作品权限受限而阻断问题报告。

#### 场景：填写并确认

- **当**用户进入反馈页
- **则**类型没有默认选中项，原生下拉选择提供「功能异常、使用建议、识别问题、账号问题、其他」。
- **则**内容为去首尾空白后 1～1000 Unicode 码点，保留内部换行；前后端统一校验，不截断超限内容保存。
- **则**手机号可留空，填写时去首尾空白后必须为 11 位中国大陆手机号 `1[3-9]` 开头，不请求微信获取手机号权限。
- **当**必填与格式校验通过并点击提交
- **则**二次确认弹窗展示类型及联系方式，并明确将提交内容、用户标识、账号状态和基础版本／设备信息用于排查；确认按钮不超过 4 字。
- **则**仅确认后调用提交接口，取消或弹窗失败不写入，确认期间和提交中不重复弹窗或发送。

#### 场景：结果与重试

- **当**保存成功
- **则**展示明确成功状态和反馈编号，清除已提交表单，提供返回「我的」或继续反馈，不承诺回复时限。
- **当**审核拒绝、审核异常、网络或数据库失败
- **则**显示准确错误并保留输入供重试；重试同一份未确认成功的反馈使用原请求标识，避免网络响应丢失导致重复入库。
- **当**用户改变反馈数据
- **则**后续提交使用新请求标识；相同标识被用于不同内容时服务端拒绝，不能返回错误反馈的成功结果。
- **当**页面隐藏或卸载
- **则**旧异步响应不能回写新页面状态或自动跳转，页面内草稿不存入长期缓存；不承诺取消已发送到云端的写入。

### 需求：可信反馈信息与私有存储

系统必须从真实云函数上下文绑定作者，并严格限制反馈内容、诊断字段和服务端回包。

#### 场景：云端入库

- **当**调用 `submitFeedback`
- **则**服务端校验类型白名单、内容类型／长度、手机号、请求标识；审核完整反馈内容，仅明确 pass 后写入，异常不放行，错误准确说明反馈内容。
- **则**服务端从真实 OPENID 保存 `ownerOpenid` 和用户 ID，从账号／管理员信息生成仅含名字、角色、开通与清理状态的快照；不接受客户端伪造身份。
- **则**只接受基础诊断白名单：小程序版本与运行环境、微信版本、基础库、平台、系统和设备型号等有界字符串；均标记为客户端上报，不能作为授权依据。
- **则**不保存校验码、密文、作品分享令牌、文件路径、微信头像／昵称授权、定位、通讯录或设备唯一标识。
- **则**写入服务端时间及初始 `status:'new'`，同一作者和请求标识并发只产生一条记录；仅返回 `{ok:true,id}`，不返回私有快照或他人反馈。
- **则**反馈写入不复用需要开通作品权限的 `userWrite`，不创建、激活或修改账号，不改变清理／撤销和作品授权。

## 修改需求

### 需求：关于与隐私说明

系统必须通过独立页面展示可信版本信息，并以弹窗承载可单独打开的隐私说明。

#### 场景：版本与更新内容

- **当**用户点击「关于与隐私说明」
- **则**打开 about 页面，所有账号状态都可访问，导航失败提供重试提示。
- **则**优先采用 `wx.getAccountInfoSync()` 返回的实际小程序版本与环境，接口缺失、异常或开发版版本为空时明确显示「本地构建／产品基线 v1.5.0」，不冒充已发布版本。
- **则**已知版本展示对应日志内容，未知实际版本展示「该版本暂无已记录的更新内容」，不误配 v1.5.0 日志。
- **则**开发／体验环境可独立展示当前源码新增的作品集分享、标题描述编辑、反馈与关于页，标记为本次开发更新，不能将未发布内容写成历史上线记录。
- **则**用准确的花艺作品 AI 打标与六维检索说明替换旧 Kimi／五维描述；模型随服务端配置使用 Qwen 或 Kimi。

#### 场景：历史与隐私

- **当**浏览历史更新日志
- **则**v1.5.0、v1.4.0、v1.3.0、v1.2.0 按新到旧平铺展示，取需求已有产品记录；无可信发布日期则不编造日期，不将 v1.6.0 规划列为已发布。
- **当**点击隐私说明
- **则**打开原生说明弹窗，清楚说明作品与标签在应用云环境按用户隔离、AI 分析按配置处理图片、明确授权的作品分享及停止／撤销边界。
- **则**补充反馈的必填内容、选填手机号、用户标识和基础诊断信息用于排查及必要联系、反馈不公开，不声称自动读取手机号或真实姓名。
- **则**弹窗只作应用内说明，不替代微信后台「用户隐私保护指引」配置，不宣称未实现的删除／自动清理承诺。

## 接口约定

- `submitFeedback({type,content,phone,requestId,diagnostics}) -> {ok:true,id}`，失败沿用 `{ok:false,error}`。
- 类型码固定 `bug/suggestion/recognition/account/other`，对应中文选项；服务端不接收任意类型字符串。
- `requestId` 为 16～64 位字母、数字、下划线或连字符；文档 ID 由服务端摘要真实 OPENID 和 requestId 生成，文本内容摘要用于检测标识复用冲突。
- `feedbackRecords` 文档只保留规范化表单、真实作者、服务端账号快照、白名单诊断、请求／内容摘要、创建时间与 new 状态。
- 关于页面使用一份共享日志来源，运行版本失败不影响浏览，诊断采集失败不阻止提交其余合法内容。

## 移除需求

移除「我的」直接弹出旧关于文案的行为，改为页面导航。其余账号管理、作品集、上传设置、清空及默认分享保持兼容。

## 验收边界

独立验证表单／确认／重试／幂等、真实身份与字段白名单、审核结果、生命周期、版本回退／未知版本、日志顺序与隐私弹窗；检查路由、JS/WXML/WXSS 及文档。真实云端集合权限、审核、事务、真机键盘与弹窗、正式发布版本分别记录，未实测项明确标注。
