# 上传中断防脏数据与云端回收实施计划

## 一、摘要与已确认范围

检查结果：当前存在未入库云文件遗留、保存响应丢失后重复入库、附加图保存结果未知时误删已关联图片的风险。本计划同时覆盖上传页、标签确认页和详情附加图，通过上传前云端登记、可取消的客户端流程、保存幂等和云端定时回收完成闭环。

用户已确认：

- 采用云端任务登记与定时回收，接受新增私有集合和部署配置。
- 离开上传/确认/附加图所在页面即放弃未保存内容；已成功保存的作品保留。
- 短暂切到后台只暂停，回前台可以继续；正常上传转确认、系统选图/图片预览不视为放弃。
- 强制关闭无法保证客户端退出回调执行，由云端超时回收兜底。
- 主图和附加图全部覆盖。

当前为计划阶段，只读检查了代码、依赖和文档，尚未修改业务代码或云端数据。用户批准后按本计划实施。

## 二、当前实现与风险依据

| 环节 | 实际代码 | 风险 |
| --- | --- | --- |
| 系统选图取消 | upload.choose/detail.addExtraImages，选图成功前未上传 | 本身不产生云文件，不应误清旧作品 |
| 文件上传 | utils/api.uploadImage，随机路径，成功后才返回fileID，UploadTask仅用于进度 | 上传完成但响应丢失时没有文件ID可清理；无可用取消句柄 |
| 上传页清空 | clearList异步删除后立即清空items | 删除失败后丢失引用，不可重试 |
| 上传页退出 | onHide仅停定时器，onUnload及processOne.finally尽力删除 | 切Tab仍继续处理；强制退出/断网删除无法保证完成 |
| 去确认标签 | 先从items移除成功项并写global.pendingList，再navigateTo | 导航失败未回滚；转交所有权不明确 |
| 确认页退出 | 没有onHide/onUnload；finish只删除skipped | 直接返回遗留；pendingList可能被再次消费，已保存状态仅在页面内存 |
| 主图保存 | accessGate.saveRecord每次records.add，confirm.saveOne收到响应才标saved | 响应丢失后重试生成重复记录；保存本张后直接返回未及时更新脏标记 |
| 附加图保存 | detail.addExtraImages本地committed标记，finally未标记时删uploaded | 云端已关联但响应丢失会误删；无上传锁、生命周期检查；提交旧extraFiles数组可能覆盖并发添加 |
| 运维清理 | adminMaintenance只扫描数据库引用 | 找不到未登记的历史孤儿文件，不能代替本轮回收 |

相关已检查文件：`miniprogram/pages/upload/upload.js/wxml/wxss`、`pages/confirm/confirm.js/wxml`、`pages/detail/detail.js/wxml`、`utils/api.js`、`app.js`、`custom-tab-bar/index.js`、`pages/my/my.js`、`cloudfunctions/accessGate/index.js/config.json/package.json/package-lock.json`、审核/分析函数和`adminMaintenance/index.js`、影响清单及维护文档。

技术事实：当前wx-server-sdk为`~2.6.3`，其已安装依赖中存在`@cloudbase/node-sdk 2.9.1`，提供`getUploadMetadata({cloudPath}) -> {data:{fileId,...}}`。其自身uploadFile也先调用这个方法再上传。因此可以在实际文件上传前获得并登记准确fileID，避免猜测环境桶名或制造占位图片。签名/临时凭证不返回页面、不写任务表或日志。

## 三、总体流程与不变量

1. 创建本人上传会话 → 为每张图片的本次尝试分配唯一任务和两条路径 → 服务端取得准确fileID并完成登记 → 页面才允许上传。
2. 原图、缩略图、检查/分析仍按现有业务顺序处理；所有异步阶段都检查取消、页面存活和当前尝试身份。
3. 主图确认后调用新的幂等提交；附加图整组提交时在事务内追加到最新作品数据。记录写入与任务标记committed在同一事务。
4. 取消/离开页面先使会话或尝试不可再提交，随后回收未提交文件。响应未知交给任务状态确认，不能按本地saved/committed布尔值直接删除。
5. 断网时保留最小任务ID待处理；重连/下次启动重试取消与状态核对。即使本地队列丢失，云端仍有准确文件位置和过期时间。

必须保持：

- 云文件一旦开始上传，已存在云端登记。
- 保存和取消竞争同一会话/任务事务：保存先成功则保留作品；取消先成功则拒绝随后提交。
- 已提交任务的文件不进入临时回收；取消一个会话不删除已保存作品或其它会话。
- 保存重试返回同一记录/同一次附加图追加，不能重复创建或重复追加。
- 不以删除任务文档代替删除文件；清理失败保留任务、引用与重试时间。
- 不覆盖同一尝试路径重试：重试先放弃旧尝试，新尝试使用新ID/路径，晚返回不能污染新尝试。

## 四、云端数据与接口

### 4.1 新增私有集合uploadJobs

同一集合保存两类文档，客户端权限为`read:false/write:false`，全部通过云函数访问。

- 会话：`type:'session'`、真实`ownerOpenid`、账号`uploadVersion`快照、`kind:'primary'|'extra'`、附加图`targetRecordId`、`state:'open'|'closed'`、`closeReason`、`createdAt`、`expiresAt`、`gcDueAt`、`gcLease/leaseUntil`、`gcCursor`及尝试计数。
- 图片尝试：`type:'image'`、`sessionId`、真实owner、逻辑图片slot、`state:'pending'|'abandoned'|'cleaning'|'cleaned'|'committed'`、`fileID/thumbFileID`及两条cloudPath、`recordId`、`commitFingerprint`、`createdAt`、清理错误/次数/下次时间和墓碑截止时间。
- 会话/尝试ID为服务器按真实OPENID与客户端随机requestId生成的确定性摘要；重复登记返回原任务，同requestId参数冲突明确拒绝。页面不能传作者、状态、路径或任意fileID指定待删文件。
- 新路径保留既有归属前缀，使用`userFiles/<hash>/works/uploads/<session>/<attempt>.<ext>`与`thumbs/uploads/...`。保存后不搬移、不复制图片，状态决定归属；旧记录路径不改。
- 初始选图仍最多9张；附加图最多8张；会话最多100次尝试以限制异常反复登记，超出需重新选图建会话。路径扩展名规范化为1～10位小写字母/数字，默认jpg，无路径字符。
- `createdAt`使用serverDate，期限/租约使用服务端毫秒时间。会话从创建起最多24小时；背景暂停不无限延长。超过期限回来明确提示该批已失效，请重新选图。
- 索引按实际查询建立：会话队列`(type,gcDueAt,_id asc)`，本人/撤销关闭扫描`(type,ownerOpenid,state,_id asc)`，图片扫描`(type,sessionId,_id asc)`；ID定位不新增索引。已有同key索引复用，不删除重建。

### 4.2 在accessGate中增加上传模块

新增`cloudfunctions/accessGate/upload-jobs.js`，由index.js显式注入db/cloud/userWrite/owner等既有依赖，避免改动作品集/反馈内部协议。

拟定接口：

| action | 输入 | 结果/规则 |
| --- | --- | --- |
| beginUploadSession | requestId,kind,targetRecordId? | sessionId,expiresAt；创建前鉴权，extra核验本人目标作品、非删除中 |
| prepareUploadJob | sessionId,requestId,slot,originalExt,thumbExt | jobId及两组cloudPath/fileID；获取元数据后事务确认会话仍open且未过期，再登记；失败不启动上传 |
| readUploadSession | sessionId | 当前会话状态、本人任务状态与已提交recordId；不返回签名/凭证 |
| abandonUploadJob | sessionId,jobId | 原子放弃尚未提交的旧尝试，安排清理；已committed只返回状态 |
| closeUploadSession | sessionId,reason | 关闭未关闭会话，安排未提交文件清理；幂等，不回滚committed |
| closeOwnUploadSessions | cursor? | 仅关闭真实本人未完成会话，每批10个并返回nextCursor/hasMore，供清空作品/退出补偿使用 |
| commitUploadRecord | sessionId,jobId,tags | 同一事务保存一条作品并标任务committed，返回固定recordId；相同提交重试返回原结果，参数冲突拒绝 |
| commitExtraUploads | sessionId,jobIds | 同事务读取最新目标作品并追加整组附加图、标全部任务committed；不得部分追加，不用页面旧数组覆盖 |

状态查询/放弃/关闭只要求真实调用者拥有该会话，不要求账号仍开通，便于撤销或失效后安全核对与清理；创建/提交仍用userWrite防撤销竞态。查询不授权其它作品或其它作者。首次会话在同一账号事务生成永久随机uploadVersion，会话绑定该版本，提交必须仍匹配；撤销轮换版本，账号被运维删除重建后不继承版本，旧会话不能再提交。新增账号字段不改变portfolioVersion或既有分享规则。

主图记录ID由owner与jobId确定，标签fingerprint按固定白名单字段顺序规范化后摘要；第一次保存前固定标签快照。相同job已提交且fingerprint相同直接返回原ID。相同job改变提交内容不再新建记录，提醒到已保存作品详情编辑。

附加图提交核验：同会话、无重复job、均为pending或同组已提交、文件登记归属一致、目标作品有效；事务读取最新extraFiles后追加，总数不得超过8。另一个会话同时添加时重读最新数据，超限整次拒绝并清理本批未提交文件。重复提交同job集合返回原结果，部分已提交/混合范围拒绝。

提交前在事务外用登记的文件ID换临时URL并HEAD验证两文件存在，网络/存在状态未知时不提交；随后事务重新检查会话/任务状态。URL及下载凭证只在服务端短暂使用，HTTP超时5秒，失败可重试，不把签名URL当存在证明。取消/回收不能绕过事务状态锁删除正在成功提交的文件。

### 4.3 兼容与绕过保护

- 保留已有saveRecord/updateRecord供旧客户端与历史作品编辑；新增前端只使用上述任务提交。
- 旧API不得直接接收新`works/uploads`、`thumbs/uploads`路径建立引用，除非属于当前记录已关联文件；新登记路径仅能由任务提交建立归属，避免绕过任务状态后被回收。
- 旧未登记上传不会自动拥有云端回收保证，需用户使用更新后小程序。本轮不扫描/删除无法证明归属的历史孤儿文件，也不合并历史重复作品。
- 已保存作品删除、单件/作品集授权、账号永久版本、反馈和标签字段协议保留。后台检查/分析为只读，不因任务放弃撤回已发模型调用；旧响应不再用于保存。
- 本轮处理失败路径和资源生命周期，不开展独立图片审核、颜色约束、手填花材审核改造，不把G3/G5登记为修复。

## 五、云端回收与维护联动

### 5.1 复用accessGate定时触发器

修改`accessGate/config.json`新增`{"name":"reapUploadJobs","type":"timer","config":"0 */10 * * * * *"}`，每10分钟执行，保留原权限/60秒超时。在index.js的普通OPENID分发之前识别真正定时事件（Type=Timer、匹配TriggerName且无客户端OPENID）；普通客户端伪造timer参数必须拒绝。定时分支不接受客户端作者/路径/时间/扩大范围参数。

回收算法：

1. 用服务端now扫描gcDueAt已到的会话，每次最多10个图片任务并在45秒前停止，保存游标/下次时间供下一轮继续。
2. 对过期open会话事务关闭；未过期会话只清已明确abandoned的尝试，不清仍在处理/后台暂停的pending。
3. 清理前事务取得会话/任务短租约，将未提交任务变为cleaning；提交接口拒绝cleaning/closed，取消和提交必然串行竞争。
4. 防御核对任务的固定主图recordId或附加图targetRecordId：若已有匹配引用则保留图片并核对任务状态，不能直接删除。引用查询失败保持待清理，不猜测未保存。
5. 根据登记fileID批量删除，只把明确删除成功或明确不存在视为该文件成功；部分失败、响应缺失、超时保留引用并重试。租约过期可接管，重复调用幂等。
6. 清完文件进入cleaned墓碑，首次清理后10分钟再核查，之后每天重清已放弃路径，保留7天以覆盖取消后晚落盘；客户端不得再次使用关闭/过期job上传。此期间元数据为回收台账，不是作品。
7. 7天观察完成才移除cleaned任务；committed任务不删除文件，保留幂等结果7天后可压缩台账，旧提交过期后拒绝并要求查看现有作品，绝不重新创建。只有无待清理/墓碑任务的closed会话才移除。

明确时间边界：显式退出在线时立即关闭并尽力回收；断网的关闭请求在重连重试。强制终止且没有关闭请求，最多等待24小时过期加定时调度/失败重试。没有宣称客户端强杀能立即清完，也不宣称后台模型调用可撤销。

回收日志只记录摘要任务ID、状态、成功/失败件数、耗时、重试次数，不记openid、文件路径、签名、图片或标签正文。失败不失去任务引用。云端真实HTTP/租约/定时触发需上线前验证。

### 5.2 账号撤销、清空与运维

- `accessGate.cleanupBatch`：在账号清理结束前关闭该账号未完成上传会话，持续分批清理已登记未提交文件；失败继续保留cleanupPending和任务引用。管理员保护沿用双来源规则。
- `miniprogram/pages/my/my.js`的清空：先停止本地上传流程并调用closeOwnUploadSessions分批关闭本人未完成会话，再删除现有作品；不删除自定义词条/反馈，失败准确反馈。
- `adminMaintenance`保持不扫描/删除uploadJobs，避免按递归cloud://引用删除已committed图片或先丢台账；由唯一的accessGate回收模块负责台账清理。全平台清理仍由records分支删除已保存图片，未提交文件继续由台账回收；账号删除后uploadVersion不匹配阻止旧会话复活。只读核对默认名单，不因本轮扩展通用清库权限。
- 当前计划不执行真实撤销、清库或历史文件删除。

## 六、客户端流程与具体文件

### 6.1 新增utils/upload-flow.js

页面共享上传控制器，维护session/job、逻辑slot和attempt版本、active/pause/cancel/提交结果未知状态及UploadTask句柄；存储最小会话/任务ID和需关闭标志于专用版本化key，不长期保存图片、标签、临时路径或签名。

- 登记完成并校验页面仍拥有该控制器后才调用实际上传。
- 每个await之后和启动UploadTask之前都检查取消/当前attempt；晚到登记结果也安排关闭，不启动上传。
- 显式取消abort已存在的UploadTask，未启动的阶段不继续；已发云函数只忽略旧响应，不承诺撤回。
- 背景暂停：不自动放弃，不开启后续阶段；进行中的请求可以结束，由内存控制器接收，页面恢复重新鉴权/读会话状态后继续。
- 断网时停止开启下一张/下一阶段，当前请求失败保留任务为可重试项；重连只恢复状态核对与待关闭队列，不自动重新上传整批。用户点击重试才关闭旧attempt并新建尝试，防止重复消耗。
- 本地队列删除前必须收到云端关闭/提交状态确认；保存状态未知不直接删文件。存储失败时保留内存并提示，云端过期回收仍有效。
- 失败重试关闭旧attempt后新建job，旧attempt永远不能重新提交。

### 6.2 utils/api.js

- 新增上述session/job API包装，使用accessGate统一错误处理。
- 上传包装支持已登记路径与fileID以及controller/onTask/onProgress；不再在新流程中临时随机生成不可追踪路径。
- 保留旧函数签名兼容未触达调用，但新主图/附加图入口全部传登记上下文；成功fileID须与登记一致，否则作为失败安排核对。
- 新流程清理只传session/job给云端，不调用客户端deleteCloudFiles删待提交文件；旧作品删除逻辑保持服务端所有权。
- 每次确认成功提交或核对到已成功，立即更新dbUpdateTime，不等批次finish。

### 6.3 upload页面JS/WXML/WXSS

- 增加处理中「取消上传」与确认弹窗（确认文字最多4字），停止整个当前未保存批次并安排回收；已保存作品不在该控制器清理范围。
- choose前锁定选图入口，系统选图取消不建会话/不清旧列表。成功选新图片前可靠关闭旧批次，然后登记新会话。
- clearList先关闭会话/持久排队，再退出本地列表；断网时明确显示待回收，不静默丢引用。
- 页面离开取消当前未交接批次；短后台暂停。区分系统选图、系统预览与正常去确认标签，防止误取消。
- goConfirm设置handoff保护、将session/job/标签快照一起交接；导航失败回滚上传列表，保留可重试批次；确认页成功接管后才完成转交。
- 权限查询响应隔离，统一按canUpload识别管理员与花艺师，身份变化放弃旧批次。取消/暂停停止计时器和进度回写，新attempt不被旧响应覆盖。

### 6.4 confirm页面JS/WXML

- onLoad一次接管交接数据并立即消费/清空global.pendingList；后续不能再次把旧批次当全新未保存作品。
- 保存用稳定jobId和第一次提交标签快照；请求失败不判断未成功，先核对readUploadSession，查询失败显示“保存结果待确认”，禁用修改/重复新建，仅允许核对。
- 确认为已提交则标记保存、更新脏标记；明确仍pending且会话open才可重试同快照。手动修改标签只针对未发提交/确定失败未提交的条目。
- 保存中锁定swiper切换、标签修改/花材弹窗、跳过/取消/重复保存，避免提交快照与界面错位；隐藏时取消仅未提交任务，旧响应不setData或跳转。
- 跳过立即放弃该job，不等finish；部分保存后返回仅关闭/回收余下未提交任务。全部跳过不提示“已入库”。
- 添加「放弃未保存」入口与范围确认；系统返回无需依赖弹窗仍执行安全关闭。finish关闭会话并清理余项，跳转失败可重试，不复用pendingList。

### 6.5 detail页面JS/WXML/WXSS

- 附加图入口增加独立extrasBusy、可取消操作与控制器；防重复选择/并发上传，上传期间锁定本页编辑/删除/分享修改等会改变目标状态的操作。
- 系统选图取消不创建任务；选择成功后建extra会话，目标记录ID固定。
- 每张图片使用登记job完成上传/检查；整组通过commitExtraUploads事务追加，响应未知仅核对，不执行当前finally中的裸文件删除。
- 任一图片失败/用户取消/页面离开关闭整组未提交任务；若服务器已整组保存，关闭返回committed，保留全部图片。
- 后台暂停不取消；恢复先鉴权并核对目标记录仍有效和会话状态。目标删除/权限失效关闭未提交任务。
- 旧请求不能回写新详情、清除新会话busy或影响访客只读。单件/作品集预览和原图请求保持现有隔离。

### 6.6 app.js与页面离开判定

- App.onShow/onHide只管理前台/后台状态和控制器暂停/恢复。
- 启动/网络重连时分批处理本地待关闭队列，当前账号只核对本人任务；本地旧账号任务不用于当前页面或跨作者清理。
- 页面onHide与App.onHide先后不同，使用一次短延迟仲裁确定是真切Tab/导航还是后台，不单靠page.onHide判断退出；系统调用使用外部界面计数保护。
- 取消真正离开页面的控制器，只有upload→confirm已标记handoff例外；确认页接管失败回滚。页面onUnload兜底关闭，防重复。
- 注册的网络监听有唯一来源并正确释放/去重，不新增定时联网轮询。
