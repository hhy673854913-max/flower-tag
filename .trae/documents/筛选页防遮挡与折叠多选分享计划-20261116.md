# 筛选页防遮挡、条件折叠与多选分享实施计划

## 一、摘要

面向已开通花艺师和管理员，修复筛选页末行作品被自定义底部导航遮挡的问题，并验证作品墙同类场景；新增筛选条件展开/收起；将精选作品集创建迁移到筛选页，完成“选中分享 → 全选 / 反选 / 分享 / 取消”的操作流程。

本计划制定时仅进行了只读排查；用户批准后已完成本地实施。最终结果见根目录 `筛选与精选分享验证报告-20261116.md`，真机/其他设备与正式转发的未测边界单独保留。

## 二、现状分析

1. 工程为原生微信小程序，页面使用 JS、WXML、WXSS、JSON；`miniprogram/app.json` 注册 11 页、4 个 Tab。
2. `miniprogram/custom-tab-bar/index.wxss` 的导航固定在底部，内容高度为 `120rpx`，额外加底部安全区；`miniprogram/app.wxss` 的 `.page-tab` 已预留 `140rpx + env(safe-area-inset-bottom)`。
3. `miniprogram/pages/filter/filter.wxss` 的 `.page-filter` 同时设置纵向 flex 和 `height:100vh`。条件与作品变多时，内容可能溢出固定高度，底部 padding 不能可靠跟随内容末尾。这是与用户截图一致的静态布局风险，实际效果须通过运行时布局验证。
4. 作品墙 `pages/index/index.wxml` 使用普通 `.page.page-tab`，没有上述固定高度。现有源码未发现同样的布局缺陷，需要验证末行卡片、“加载更多”和“没有更多了”的位置。
5. 筛选页已通过 `api.fetchAllRecords()` 按服务端默认 100 条拉取本人全部作品，按同维度 OR、跨维度 AND及花材角色过滤；`compute()` 当前截断前 60 条，条件命中数量取展示数量，且 `resolveUrls()` 没有旧请求隔离。
6. `portfolio-manage` 当前提供全部分享、独立精选挑选、链接管理及标题/描述编辑。精选使用 `api.createPortfolioShare('selected', recordIds)`，服务端已校验归属、账号、删除状态、1000 件及 UTF-8 JSON 128 KiB 限制。
7. 创建后前往 `portfolio-share?portfolioToken=`，该页已有“分享给好友”、独立令牌转发和只读浏览；筛选页右上角默认分享仍是首页入口。
8. 已查看 `修改影响范围清单.md` 第 2.4、2.5、2.9、2.11 节及项目文档、记忆。当前代码与本次确认优先于历史路线图。

## 三、已确认的交互与边界

### 3.1 筛选条件

- 首次进入默认展开；手动收起状态在本次小程序会话中保留，切换 Tab 后返回不重置。不写长期本地存储。
- 条件区域顶部提供标题、展开/收起按钮及已选条件摘要。摘要展示所选标签与有效花材角色；无条件显示“未设置筛选条件”，长摘要可换行。
- 收起时所有条件控件和“清空筛选”均隐藏，无法修改条件；结果数量仍显示。
- 点击“选中分享”自动收起并锁定条件；多选期间不能展开、修改或清空。点击处理函数也要校验锁态。
- 取消多选或成功创建分享后仍保持收起，解除锁定；用户可点击展开重新调整条件。

### 3.2 结果与选择

- 显示完整命中总数；卡片首批 60 件，随后通过“加载更多”每次增加 60 件，直至全部展示。保留三列网格与缩略图优先、旧作品回退主图。
- 所有命中 ID 保存在页面实例内；展示数组与完整命中集合分开，不能用已渲染卡片数量替代命中总数。
- “选中分享”位于结果列表尾部，在卡片和分页/列表状态之后，随页面正常滚动，不固定悬浮。
- 多选时该位置原位替换成一行四按钮，顺序与文字严格为【全选】【反选】【分享】【取消】，并显示“已选 X / 命中 Y 件”。
- 卡片显示右上角多选圆圈，选中有勾选和边框反馈。多选时点击卡片切换选择，不进入详情；普通浏览时仍进入详情。
- 全选和反选作用于完整命中集合，包括尚未展示的卡片。后续加载的卡片立即反映选择状态。
- 选择以作品 `_id` 去重。单件选择、全选、反选均先验证完整候选集合的 1000 件/128 KiB 限制，超限保留原选择、提示减少数量，不截断。
- 全选在命中超过上限时整体拒绝，用户仍可逐件挑选；反选也按候选集合整体校验。零件选择禁用“分享”，允许全选和取消。
- 无筛选条件时全部本人作品视为完整命中集合，可挑选创建固定范围精选作品集；不会转成动态全部作品分享。
- 空结果或数据加载失败时不提供可用的“选中分享”；失败展示重试入口。

### 3.3 分享与入口迁移

- 点击“分享”先确认所选件数和固定范围，沿用既有精选授权说明；确认按钮“创建链接”不超过 4 字。
- 重新检查 `getAccessStatus()`、当前身份及分享权限，再调用 `createPortfolioShare('selected', recordIds)`；提交范围为本次已选 ID 的固定快照。
- 创建期间锁定重复提交、选择和取消操作，显示加载状态。
- 用户取消确认或创建失败时保留多选状态、所选作品和锁定的筛选条件；明确反馈错误。
- 成功取得令牌后解除多选、清空选择、保留筛选收起，导航至既有只读作品集预览页，由该页“分享给好友”执行微信转发。
- 已创建令牌但导航失败时，不再次创建链接：页面显示“打开已创建作品集”重试入口，并提示也可从“我的 → 作品集分享”找到该链接。
- “我的 → 作品集分享”管理页保留全部作品创建、已有链接分页、编辑标题/描述、预览/再次分享/停止。原“挑选作品分享”改为 `wx.switchTab` 跳转筛选页，提示先筛选再到列表末尾选中分享；不自动进入多选，不传递旧管理页选择。
- 管理页旧精选挑选列表、选择状态和专用事件/样式移除，避免两个挑选流程并存。

## 五、假设与技术决策

- 用户指定的是现有小程序的局部修改，沿用原生微信工程；不初始化新模板、不迁移 Taro、不增加依赖。技能中的新项目生成流程不扩大本次任务范围。
- 每批 60 件是客户端展示批次，不改 `fetchAllRecords` 的服务端100条拉取或作品墙20条分页。
- 管理页跳转筛选页不自动选择、不新增全局导航参数；进入已有筛选状态后由用户调整或选择。
- “分享”复用现有两步流程：创建精选授权并打开预览，再在预览转发。避免异步创建尚未完成时生成微信分享卡片。
- 本次只实施前端与相关文档，不提交、不部署、不上传发布或更改云端数据。
- 临时验证脚本、测试副本、调试日志放项目外临时目录；用户可阅读的正式验证报告放项目根目录并以可点击链接交付。
